Fifolio architecture

A local tool that attributes securities disposals to acquisitions under the German FIFO rule, per account, and reports the raw gain or loss in EUR.

These pages follow the arc42 template. They give a structural overview of the system: its goals, constraints, boundary, strategy and building blocks. They do not restate the rules.

The specification in design/ is the only source of truth. These pages summarize it and cite its identifiers (DOM-058, DEC-024, …), which link to the document that declares them. Where a page and design/ disagree, design/ wins and the page is out of date.

How to read these pages

  • Built and planned. Much of the system is specified but not yet built. Where it matters, a block carries a status: built exists and is tested, partial exists in part, planned is specified and not yet started. Status is taken from the code and PLAN.md at commit c04362c (2026-09-24).
  • Identifier prefixes. DOM domain, ARC architecture, SRV server, CLI client, IMP importers, TST testing, DEC decisions, OQ open questions, FIF work items in PLAN.md.
  • Links into design/ open Markdown source files. Most browsers show them as plain text; search the page for the identifier.
