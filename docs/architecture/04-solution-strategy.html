4 · Solution strategy

The handful of fundamental decisions that shape everything else, and how each quality goal from section 1.2 is met.

4.1 Core ideas

If you remember nothing else about the design, remember these five.

  1. Import is separate from derivation. A broker row becomes an immutable source record. Transactions are derived from one or more records afterwards, because one real event is often several rows (a merger paid out over three bookings, a tender plus its reversal). DOM-042 DEC-007
  2. A transaction is a sum type. There are six variants: buy and transfer_in open parcels, sell, expiration and transfer_out close them, and split rescales them. Each carries only its own fields. Corporate actions are expressed as these variants, not as a separate entity. DOM-010 DOM-081 DEC-024
  3. Attribution stores quantities; money is derived. An allocation holds an opening, a closing and a quantity, nothing else. Every EUR figure is computed from the parent transactions when it is read, so it can never drift from its sources. Transactions in an attribution are immutable. DOM-058 DOM-069 DEC-005
  4. The system proposes, the human approves. The server computes the FIFO proposal. The user can only approve or decline it. Approval posts back a fingerprint of exactly what was shown, so figures that changed in between are refused. DOM-054 SRV-040 SRV-050
  5. Refuse rather than guess. An unknown input rejects the whole file. Missing history blocks attribution with a named shortfall. A missing FX rate is an error. Every open point in the specification blocks the work that depends on it. DEC-019 DOM-057 ARC-019

4.3 Top-level decomposition

  • A local client and server. The server is the single writer of the database and the single implementation of the FIFO rules. The client is a thin HTTP client with no domain logic, and it does not even link fifolio-core. ARC-003 ARC-005 DEC-018
  • A pure domain library. fifolio-core holds the domain model, the FIFO engine, the importers, FX resolution and storage. It has no HTTP and no terminal. External services enter through injected ports (RateFeed, RateTable), so the core is tested without a network. ARC-002 TST-020
  • Reports are subcommands, not screens. This way they can be piped, redirected and diffed. CLI-008

4.4 Approaches to the quality goals

Quality goalApproachRefs
1 · Correct figures
  • Decimals only, with fixed scales. Rounding is done before a boundary, and storage refuses an unrounded value instead of rounding it silently.
  • One allocation formula for every closing variant. Drift is absorbed by the last share, so shares always sum exactly to their parent.
  • A gain is computed from the rounded shares, so every row reconciles with its columns.
  • The booked EUR total governs every calculation. The unit price is only displayed.
  • Effective quantity after splits is measured at the closing's position, as an exact rational.
  • Property tests over generated input. Arithmetic is tested on synthetic cases that can be derived by hand.
 ARC-010 DOM-059 DOM-061 DOM-125 DOM-085 DOM-089 DOM-113 TST-010 TST-015
2 · Fail safe
  • An unrecognized row type that names a security rejects the file. An unrecognized type that names none is counted and named in the import summary.
  • A file spanning more than one calendar year, or naming the wrong account, is refused.
  • A pending record blocks attribution for that security in that account.
  • Closings are attributed in canonical order. A shortfall is reported, never approximated.
  • The FX fallback is bounded to seven days. After that it is an error.
  • Invariants are enforced by storage as well as by the domain.
 DEC-022 IMP-001 IMP-003 DOM-049 DOM-066 DOM-057 ARC-027 TST-004
3 · Auditable
  • Source records keep the raw row (a verbatim CSV line, or a canonical JSON rendering of a spreadsheet row) and are never edited.
  • A transaction consumes the records it answers and cites any others it rests on.
  • Native figures, EUR figures, the rate, its source and its own date are all stored.
  • User input is a first-class manual entry, cited next to the imported rows.
  • No endpoint edits a transaction, and none creates one from nothing.
 DOM-007 DOM-008 DOM-120 DOM-101 DOM-028 DOM-048 SRV-034 SRV-054
4 · Reproducible
  • Record identity is the broker's own reference, or else a hash of the business fields, scoped to the account. This makes import idempotent.
  • Order is computed from file content when the file is read, and stored. Canonical order is (trade date, order, batch age).
  • An import batch is the unit of undo.
  • Manual entries are a separate entity that references records by broker identity. They survive an undo and reconnect when the rows return.
  • The ECB cache is insert-only and never rewrites a day it holds.
  • Manual entries export to and replay from a versioned JSON file.
 DOM-023 DOM-040 DOM-111 DOM-017 DOM-099 DEC-038 ARC-028 DEC-020
5 · Confidential
  • Bound to loopback only, and single user.
  • The real exports are gitignored. An anonymizer (tools/anonymize-exports) perturbs amounts and keeps structure, so CI runs on committed fixtures.
 ARC-022 TST-012 TST-028

4.5 Organizational approach

The specification is executable as a process. Stable requirement ids connect the specification, the plan (PLAN.md, FIF-nnn items) and the tests. A fixed cycle of agents turns decided requirements into code; see the organizational constraints in section 2.3. Undecided points are kept visible in open-questions.md and block only the work that depends on them.
